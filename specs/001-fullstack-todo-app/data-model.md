## Entity Definitions

### User (Better Auth Managed)

**Note**: Better Auth creates and manages its own user table. We reference user IDs but do not create the User model ourselves.

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| id | string | Primary Key | UUID generated by Better Auth |
| email | string | Unique, Not Null | User's email address |
| name | string | Nullable | Display name (optional) |
| emailVerified | boolean | Default: false | Email verification status |
| image | string | Nullable | Profile image URL (optional) |
| createdAt | datetime | Auto-generated | Account creation time |
| updatedAt | datetime | Auto-updated | Last account update time |

### Task (Application Managed)

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| id | integer | Primary Key, Auto-increment | Unique task identifier |
| user_id | string | Foreign Key → User.id, Not Null, Indexed | Owner of the task |
| title | string | Not Null, Length 1-200 | Task title (required) |
| description | string | Nullable, Max 1000 | Task description (optional) |
| completed | boolean | Not Null, Default: false | Completion status |
| created_at | datetime | Auto-generated, Not Null | Task creation timestamp |
| updated_at | datetime | Auto-updated, Not Null | Last modification timestamp |

## SQLModel Implementation

```python
# models.py
from sqlmodel import SQLModel, Field
from datetime import datetime
from typing import Optional

class TaskBase(SQLModel):
    """Base fields shared between create, update, and read operations."""
    title: str = Field(min_length=1, max_length=200)
    description: Optional[str] = Field(default=None, max_length=1000)

class TaskCreate(TaskBase):
    """Schema for creating a new task."""
    pass

class TaskUpdate(SQLModel):
    """Schema for updating an existing task. All fields optional."""
    title: Optional[str] = Field(default=None, min_length=1, max_length=200)
    description: Optional[str] = Field(default=None, max_length=1000)

class Task(TaskBase, table=True):
    """Database model for tasks."""
    id: Optional[int] = Field(default=None, primary_key=True)
    user_id: str = Field(index=True, nullable=False)
    completed: bool = Field(default=False)
    created_at: datetime = Field(default_factory=datetime.utcnow)
    updated_at: datetime = Field(default_factory=datetime.utcnow)

class TaskRead(TaskBase):
    """Schema for reading task data (API response)."""
    id: int
    user_id: str
    completed: bool
    created_at: datetime
    updated_at: datetime
```

## Validation Rules

### Task Title (FR-008, FR-017)
- **Required**: Cannot be empty or whitespace-only
- **Length**: 1-200 characters
- **Validation**: Strip leading/trailing whitespace before validation

### Task Description (FR-009)
- **Optional**: Can be null or empty string
- **Length**: Maximum 1000 characters when provided

### User Isolation (FR-007)
- All queries MUST filter by `user_id`
- JWT `sub` claim must match `user_id` in URL path
- Mismatch returns 403 Forbidden

## State Transitions

### Task Completion Status

```
┌──────────┐                    ┌───────────┐
│ Pending  │ ──── complete ───▶ │ Completed │
│(default) │                    │           │
└──────────┘ ◀── uncomplete ─── └───────────┘
```

- **Initial State**: `completed = false` (pending)
- **Transition**: Toggle via `PATCH /api/{user_id}/tasks/{id}/complete`
- **Reversible**: Users can toggle back to pending

## Database Migration Notes

### Initial Schema Creation

```sql
-- Task table (User table managed by Better Auth)
CREATE TABLE task (
    id SERIAL PRIMARY KEY,
    user_id VARCHAR NOT NULL,
    title VARCHAR(200) NOT NULL,
    description VARCHAR(1000),
    completed BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE INDEX ix_task_user_id ON task(user_id);
CREATE INDEX ix_task_completed ON task(completed);
```

### Foreign Key Consideration

**Note**: We intentionally do NOT create a foreign key constraint from `task.user_id` to Better Auth's user table because:
1. Better Auth manages its schema independently
2. The table name may vary based on Better Auth version/config
3. User validation happens at the application layer via JWT verification

### Timestamp Auto-Update

For `updated_at` auto-update, use SQLModel's `on_update` or handle in application code:

```python
# In route handlers, before saving updates:
task.updated_at = datetime.utcnow()
```
